MAVIS Desktop for Windows and Ubuntu / Zorin OS

For Linux distributors (developer-only, not an end-user step):
  python3 packaging/deb.py dist/mavis.deb

For Linux users:
  1. Download mavis.deb and open it in your graphical package installer.
  2. Click Install and approve the system's normal installation prompt.
  3. MAVIS's installer automatically provisions FFmpeg, Python, the local
     Ollama service and qwen3:4b model, and the Qwen voice engine and its
     checksum-verified models. Internet and several GB of free disk space
     are necessary for this one-time installation.
  4. Launch MAVIS from the Applications menu. The first launch automatically
     creates an isolated Python environment and installs its Python libraries.
     MAVIS then opens its browser-based local studio.

No terminal commands or separate AI/model installs are required of end users.
There is no subscription or billing requirement in this temporary build.
The original billing code is retained in Git history for later reinstatement.

YouTube publishing still requires the user's own Google/YouTube authorization
and channel configuration. Channel-specific media and animation assets must be
provided by the user. No installer can create their Google credentials, channel,
voice instructions or copyrighted channel assets.

The installer runs third-party network downloads at installation time; it fails
clearly rather than claiming a working install when provisioning is incomplete.
A failed download can be retried by rerunning the package installation. Check
the package-manager logs for error details. The machine must run systemd.

OFFLINE HARDWARE ACTIVATION
  MAVIS launches its browser activation screen on an unlicensed computer.
  The user copies the displayed device code to the software publisher.
  The publisher issues a signed JSON license with the offline command:
    python3 packaging/issue_activation.py --private-key /secure/mavis-activation-private.pem --device DEVICE_CODE --output activation.json
  The user pastes the returned JSON into MAVIS's activation screen.
  The license remains usable offline on that computer, without payments or a
  remote licensing server. Copying the install or workspace to a computer with
  a different machine-id will not validate the same license.
  IMPORTANT: Store the private signing key securely, NEVER commit it to GitHub.
  OS reinstall or machine-id changes may require a replacement activation.
  This is a distributor-controlled license lock, not tamper-proof DRM against
  source modification; the publicly available source can be modified.

DAILY VIDEO OUTPUT
  In the browser dashboard, select Videos per day under Production schedule
  and click Save schedule. Default: 1 video/day. Maximum: 5 videos/day.
  MAVIS spaces the selected publication times evenly through the local day
  relative to the configured primary publication time (6 PM by default).
  The setting is saved in the user's workspace and read by the scheduler.
  This control changes the frequency but does not turn on automatic scheduling
  or bypass initial YouTube channel and scheduler validation.

WINDOWS DESKTOP INSTALLATION (Windows 10/11 x64)
  1. Download MAVIS-Setup-0.2.0-Windows.exe and double-click it.
  2. Approve Windows's administrator permissions and installation prompts.
  3. The Windows installer adds the MAVIS desktop shortcut and bundles the
     Linux engine .deb. Its guided first-run setup installs Ubuntu in WSL 2
     and provisions the production dependencies and AI models inside Ubuntu.
     WSL installation may require virtualization and a Windows restart.
     After restarting, click the installed MAVIS desktop icon again to
     continue setup; no manual WSL or terminal commands are required.
  4. Click the MAVIS icon to open the browser-based local studio, then
     activate the computer using a signed license as described above.

Windows currently runs the Linux production engine under WSL; it is NOT a
native Windows voice renderer. First setup requires internet, many GB of
disk space, and several large downloads. The Windows installer build and
script syntax are checked in CI; actual WSL installation on a fresh Windows
computer must still be validated. Windows may display a SmartScreen warning
for an unsigned installer. Do not bypass enterprise security policies.
